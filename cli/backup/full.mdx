title: "backup full — upload a complete ZFS snapshot"
sidebarTitle: "full"
description: "Upload an entire ZFS snapshot to blob storage as a full backup. Use this for the first backup of a volume or as a periodic full baseline before chaining incrementals."
---

`backup full` streams a complete ZFS snapshot to your configured S3-compatible blob storage. Use it when setting up a new volume for the first time or when you want to establish a fresh baseline after a series of incremental backups. Full backups are larger than incrementals but are self-contained — they can be restored without any prior snapshot chain.

## Usage

```bash
zfs-backup-blob backup full [flags]
```

## Flags

<ParamField query="-s, --snap" type="string" required>
  The ZFS snapshot to back up, in `pool/vol@snapshot` format. The snapshot must already exist on the local ZFS pool before running this command.

  **Example:** `zfs-pool/volume1@backup_blob_2024-08-11T00-00-00Z`
</ParamField>

<ParamField query="-c, --configPath" type="string" default="~/.bbackup.yaml">
  Path to the configuration file. Inherited from the root command.
</ParamField>

<ParamField query="-l, --logLevel" type="string" default="disabled">
  Log verbosity level. Set to `debug` for verbose output or `disabled` to suppress logs. Inherited from the root command.
</ParamField>

## Example

```bash
zfs-backup-blob backup full --snap zfs-pool/volume1@backup_blob_2024-08-11T00-00-00Z
```

<Note>
  For automated and recurring backup workflows, the `group snapshot` + `group sync` command pair is the recommended approach over calling `backup full` directly. It handles snapshot naming, type selection, and upload in a single coordinated operation across all volumes registered in a group.
</Note>
