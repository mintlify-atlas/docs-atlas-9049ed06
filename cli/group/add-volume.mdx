---
title: "group add-volume — register a ZFS volume for backup"
sidebarTitle: "add-volume"
description: "Register a ZFS volume with a named backup group, or the default group if none is specified, using the --volume and --group flags to control which volume and group to target."
---

Backup groups let you batch together multiple ZFS volumes so that snapshot, sync, and trim operations can be applied to all of them in a single command. `group add-volume` registers a ZFS volume with a group so it is included in those batch operations. If you do not specify a group, the volume is added to the `default` group.

## Usage

```bash
zfs-backup-blob group add-volume [flags]
```

## Flags

<ParamField body="--volume" type="string" required>
  The ZFS volume or filesystem to register. Must be a valid ZFS dataset path, for example `pool/vol1`.
</ParamField>

<ParamField body="-g, --group" type="string" default="default">
  The backup group to add the volume to. Groups are arbitrary names you choose to organise your volumes. Omit this flag to use the `default` group.
</ParamField>

<ParamField body="-c, --configPath" type="string" default="~/.bbackup.yaml">
  Path to the configuration file. Inherited from the root command.
</ParamField>

<ParamField body="-l, --logLevel" type="string" default="disabled">
  Log verbosity level. Accepted values: `debug`, `disabled`. Inherited from the root command.
</ParamField>

## Examples

```bash
# Add a volume to the default group
zfs-backup-blob group add-volume --volume pool/volume1

# Add a volume to a named group
zfs-backup-blob group add-volume --volume pool/volume1 --group production
```

<Note>
  Volume registrations are persisted in the config file at `~/.bbackup.yaml` (or the path given by `--configPath`). Run [`group list-volumes`](/cli/group/list-volumes) at any time to see every volume that has been registered and the group it belongs to.
</Note>
