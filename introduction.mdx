ZFS Backup Blob is an open-source command-line tool that backs up ZFS snapshots to S3-compatible blob storage. It removes the operational burden of maintaining a dedicated ZFS backup server — instead, all you need is a bucket in any S3-compatible service. Designed for Linux and macOS sysadmins managing ZFS pools, ZFS Backup Blob keeps things deliberately simple: it handles both full and incremental snapshot transfers, optional in-flight encryption, configurable bandwidth throttling, and automated retention policies, all driven by a single YAML config file.

## How it works

ZFS Backup Blob models every backup operation as a **stage pipeline**. Data flows from a **ZFS source stage** through zero or more **middleware stages** and arrives at an **S3 sink stage**. Each stage is declared in your YAML config file (default: `~/.bbackup.yaml`) under the `stages` key, and every stage except the sink carries a `remote` pointer to the next stage in the chain.

A minimal pipeline looks like this:

```yaml
stages:
  zfs:
    type: zfs
    remote: s3
  s3:
    type: s3
    bucket: my-backup-bucket
    accessKey: AKIAIOSFODNN7EXAMPLE
    accessSecret: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
    region: us-east-1
```

You can insert a `crypt` stage to encrypt data before it leaves your machine, a `throttle` stage to cap upload and download speeds, or both together:

```yaml
stages:
  zfs:
    type: zfs
    remote: throttle
  throttle:
    type: throttle
    remote: crypt
    writeSpeed: 52428800
    readSpeed: 52428800
  crypt:
    type: crypt
    remote: s3
    password: "a-strong-passphrase"
  s3:
    type: s3
    bucket: my-backup-bucket
    accessKey: AKIAIOSFODNN7EXAMPLE
    accessSecret: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
    region: us-east-1
```

Stages are the only extension point in ZFS Backup Blob — scheduling is intentionally left to external tools such as cron.

## Key features

<CardGroup cols={2}>
  <Card title="Full & Incremental Backups" icon="layer-group">
    Full backups store the entire ZFS volume. Incremental backups store only the delta since the previous snapshot, significantly reducing storage costs and transfer time.
  </Card>
  <Card title="AES-256-GCM Encryption" icon="lock">
    Add a `crypt` stage to encrypt all snapshot data with AES-256-GCM before it leaves your machine. The encryption password is set in your config file and never sent to the remote.
  </Card>
  <Card title="Bandwidth Throttling" icon="gauge">
    Add a `throttle` stage to cap upload (`writeSpeed`) and download (`readSpeed`) throughput in bytes per second. Useful for keeping backups from saturating a production network link.
  </Card>
  <Card title="S3-Compatible Storage" icon="cloud">
    Works with AWS S3, Backblaze B2, MinIO, and any other S3-compatible API. Point the `baseEndpoint` field at your provider's endpoint and ZFS Backup Blob handles the rest.
  </Card>
  <Card title="Volume Groups" icon="folder-tree">
    Organize multiple ZFS volumes into named groups. Run a single `group snapshot` or `group sync` command to create and upload snapshots for all volumes in the group at once.
  </Card>
  <Card title="Automated Trim Policies" icon="scissors">
    Define retention rules with a simple string-based DSL (e.g. `IFIFIF` keeps the last 3 full and 3 incremental backups). Separate policies control remote blob storage and local ZFS snapshots.
  </Card>
</CardGroup>

## Release channels

ZFS Backup Blob ships through two release channels:

- **beta** — stable releases recommended for everyday use.
- **next** — nightly builds for those who want the latest changes; use at your own risk.

Most users should install from the **beta** channel. See the [Installation](/getting-started/installation) page for platform-specific instructions.
